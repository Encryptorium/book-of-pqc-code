SLH-DSA implementation for Chapter 17 of the Encryptorium Book of Post-Quantum Cryptography. `adrs.py` is the 32-byte address structure and its 22-byte compressed form; `tweakable.py` instantiates the six hash functions for both the SHA2 and SHAKE families; `wots.py`, `fors.py` and `hypertree.py` build the three components; `slh.py` assembles them. `params.py` carries all twelve FIPS 205 parameter sets. Standard library only (`hashlib`, `hmac`, `struct`, `math`, `os`, `dataclasses`); no external dependencies.

Unlike the Chapter 16 package, this one targets the standard itself rather than a teaching variant. `pytest tests/ch17` checks it against the official NIST ACVP vectors: key generation byte for byte at all twelve parameter sets, signature verification accepting the valid cases and rejecting the invalid ones at all twelve, and signature generation byte for byte at the six `f` sets. The divergences below are what remains.

**Only the internal interface is implemented, and one function name is a trap.** FIPS 205 Section 10 wraps the internal algorithms in `slh_sign` (Algorithm 22), `hash_slh_sign` (Algorithm 23), `slh_verify` (Algorithm 24) and `hash_slh_verify` (Algorithm 25), each of which prefixes a domain separator and a caller-supplied context string, and in the pre-hash case an OID, before the internal signer sees the message. None of those four is implemented here. **The `slh_sign` and `slh_verify` exported by this package are not FIPS 205's `slh_sign` and `slh_verify`.** They take no `ctx` argument and prefix nothing; `slh_sign` is a convenience wrapper that picks `opt_rand` and calls `slh_sign_internal` (Algorithm 19): `os.urandom(n)` by default, the hedged variant, or PK.seed when called with `randomize=False`, the deterministic variant. `slh_verify` is Algorithm 20. A signature produced here will not verify against a conforming implementation driven through the external interface, and vice versa.

**No side-channel or fault hardening.** FIPS 205 Section 3.2 says that "care must be taken to protect implementations against attacks, such as side-channel attacks or fault attacks". Nothing here does. Chain lengths in `wots_sign` depend on the message digits, which is the timing leak Chapter 18 describes, and the verify-after-sign countermeasure it recommends is not implemented. Comparisons are ordinary Python `==` and are not constant-time.

**Parameter derivation uses floating point.** Six sites take a base-2 logarithm or divide before rounding: `SLHDSAParams.__post_init__` at three of them, `base_w`, and the checksum width computation in both `wots_sign` and `wots_pk_from_sig`. FIPS 205 Section 3.1 states that implementations "shall not use floating-point arithmetic, as rounding errors in floating point operations may lead to incorrect results in some cases", and gives the integer form of $\ell_2$ as Algorithm 1 (`gen_len2`). At all twelve approved parameter sets the two forms agree, so the shortcut is invisible here, but it would not be acceptable in a conforming implementation. Note that this is not a hypothetical class of defect in this package: `md_len` computed the digest length by summing three field widths in bits and rounding once, where Algorithm 19 rounds each field separately, and it was wrong at four of the six parameter sets until 2026-08-10.

**Passing the ACVP vectors is not validation.** These are the public test vectors from the NIST ACVP-Server repository, run offline against committed fixtures. This is not a CMVP-validated cryptographic module, and nothing here has been reviewed for production use.

**Randomness.** `slh_keygen` draws SK.seed, SK.prf and PK.seed from `os.urandom`, and `slh_sign` draws `opt_rand` from the same source, which is the hedged variant. FIPS 205 requires an approved random bit generator supporting at least $8n$ bits of security strength; `os.urandom` is the platform CSPRNG and is not such an approved generator.

The package exists to be read and rebuilt rather than deployed. `exercises/ch17-slh-dsa` is the same package with 25 of its functions replaced by stubs. The ones the chapter prints in full arrive already implemented, so the rebuild track never asks anyone to retype the page: the ADRS field accessors, its compressed form, the WOTS+ public-key routine, and the XMSS node recursion. What is stubbed is what the chapter explains but does not print, which includes the tweakable hashes at their SHAKE and SHA-512 branches.
