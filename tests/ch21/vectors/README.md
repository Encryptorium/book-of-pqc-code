# Chapter 21 HQC reference KAT fixtures

This directory holds Known-Answer-Test (KAT) vectors from the official HQC
reference implementation. The fixtures are not committed to the repository
because they are large for a source tree: the three `.rsp` files come to
about 11 MB. The `test_vectors.py` suite skips gracefully when the fixtures
are absent and runs structural checks against them when present.

## Obtaining the fixtures

The official implementation lives at <https://gitlab.com/pqc-hqc/hqc>, linked
from the Resources page of <https://pqc-hqc.org>. Its `kats/ref/` directory
holds one subdirectory per parameter set; copy the `.rsp` file from each into
this directory, keeping its upstream name:

| Parameter set | Upstream path |
| --- | --- |
| HQC-1 | `kats/ref/hqc-1/PQCkemKAT_2321.rsp` |
| HQC-3 | `kats/ref/hqc-3/PQCkemKAT_4602.rsp` |
| HQC-5 | `kats/ref/hqc-5/PQCkemKAT_7333.rsp` |

The filename carries the decapsulation-key length in bytes. `kats/x86_64/`
holds the same vectors regenerated by the AVX2 build; either set works, since
the two implementations agree by construction.

Each file contains 100 test vectors in the NIST KAT format
(`count`, `seed`, `pk`, `sk`, `ct`, `ss` blocks separated by blank lines).

Sizes and names in this directory follow the 22 August 2025 HQC
specification, which supersedes the Round-4 submission. That earlier package
is still downloadable from the Resources page as `archive_submissions.zip`,
and its KAT files carry different sizes; do not mix the two.

## Why the toy does not verify byte-for-byte

The Chapter 21 toy deliberately strips the reference HQC stack to its
IND-CPA core:

| Reference HQC | Chapter 21 toy |
| --- | --- |
| Concatenated outer Reed-Solomon and inner duplicated Reed-Muller code | plain repetition only |
| Salted FO (HHK) transform wrapping IND-CPA to IND-CCA2 KEM | IND-CPA only |
| `n = 17669` (HQC-1) / 35851 / 57637 | `n = 83` (toy) |
| `DFR < 2^-128` (specification target) | `DFR ~ 0.6%` (toy) |
| Deterministic-random-bit-generator schedule | seeded `random.Random` |

Forcing the toy to reproduce the reference KAT byte-for-byte would mean
re-introducing the concatenated code, the FO wrapping, the full randomness
schedule, and parameters matching each reference set. That is out of scope
for the pedagogical chapter. The chapter states the same four divergences
under "Reference KAT compliance", and its "The Fujisaki-Okamoto wrapper"
section names the IND-CPA to IND-CCA2 gap explicitly.

## What `test_vectors.py` checks when fixtures are present

- Each `.rsp` file exists, is non-empty, and parses into the NIST KAT
  block structure (`count`, `seed`, `pk`, `sk`, `ct`, `ss`).
- The count of vectors per file is 100.
- Byte lengths of `pk`, `sk`, and `ct` match the specification for each
  parameter set: `pk` 2241 / 4514 / 7237, `sk` 2321 / 4602 / 7333, and
  `ct` 4433 / 8978 / 14421 at HQC-1, HQC-3 and HQC-5.

It does NOT attempt to run the toy implementation against the reference
KAT. A reference-compliant HQC implementation would be the right home for
that test; the chapter's toy is not the right target.
